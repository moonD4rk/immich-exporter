# immich-exporter

[![Go CI](https://github.com/moond4rk/immich-exporter/actions/workflows/ci.yml/badge.svg)](https://github.com/moond4rk/immich-exporter/actions/workflows/ci.yml) [![codecov](https://codecov.io/gh/moond4rk/immich-exporter/branch/main/graph/badge.svg)](https://codecov.io/gh/moond4rk/immich-exporter) [![Go Reference](https://pkg.go.dev/badge/github.com/moond4rk/immich-exporter.svg)](https://pkg.go.dev/github.com/moond4rk/immich-exporter) [![Go Report Card](https://goreportcard.com/badge/github.com/moond4rk/immich-exporter)](https://goreportcard.com/report/github.com/moond4rk/immich-exporter) [![License](https://img.shields.io/github/license/moond4rk/immich-exporter)](https://github.com/moond4rk/immich-exporter/blob/main/LICENSE)

A comprehensive Prometheus exporter for **Immich photo-library content** — ~100 metrics covering assets, cameras & EXIF, geography, people & faces, per-user storage & quota, albums & sharing, jobs, integrity checks, database backups, and server health. Ships with a large Grafana dashboard (world map included) and ready-made alert rules.

It is **complementary to Immich's built-in OpenTelemetry**: Immich's own telemetry exposes _performance_, never library _content_. All data is read from the public Immich REST API with an API key — the database is never touched.

## Features

- **~100 content metrics** Immich's telemetry doesn't expose — assets by type/year/rating/state/file size, cameras & lenses, geo distribution by country and city, people & faces, per-user storage & quota, albums & shared links, tags, memories, duplicates, stacks, external libraries, workflows, and every job-queue depth.
- **Immich's own upkeep** — what its integrity checks flagged, its database backups (count, size, age of the newest), maintenance mode, and whether its release check is still fresh (a disabled check no longer reports a false "up to date").
- **Two-tier polling** with bounded-concurrency fan-out: cheap counters every 2 minutes, and the expensive work (per-camera and per-person breakdowns, the map, duplicates, stacks) every 15. An atomic snapshot is emitted fresh on every scrape, so vanished label combinations never linger as stale series.
- **Self-diagnosing** — `immich_exporter_collector_success` and `_duration_seconds` per collector, so a key without a permission or an endpoint an older Immich lacks shows up by name instead of as an empty panel.
- **Admin auto-detection** — full coverage with an admin key, graceful degradation with a non-admin or scoped one.
- **Single ~13 MB static binary**, distroless `nonroot` image (multi-arch, signed with cosign, SBOM and provenance attached); exports its own `go_*` / `process_*` runtime metrics too.
- **Batteries included** — Grafana dashboard (~70 panels) and [alert rules](deploy/alerts.yml), both CI-checked on Prometheus and VictoriaMetrics, plus a Docker Compose stack and Kubernetes manifests.

## Quick start

### Docker

```sh
docker run -d --name immich-exporter -p 8000:8000 \
  -e IMMICH_HOST=immich-server -e IMMICH_API_TOKEN=<your-key> \
  ghcr.io/moond4rk/immich-exporter:latest
```

Metrics are served at `http://localhost:8000/metrics`. Use an **admin** API key (Account Settings → API Keys) for full coverage.

### Binary

Download from the [releases page](https://github.com/moond4rk/immich-exporter/releases), or install with Go:

```sh
go install github.com/moond4rk/immich-exporter/cmd/immich-exporter@latest
IMMICH_HOST=immich-server IMMICH_API_TOKEN=<your-key> immich-exporter
```

### Full monitoring stack

[`deploy/docker-compose.yml`](deploy/docker-compose.yml) brings up the exporter + Prometheus + Grafana with the dashboard and datasource auto-provisioned:

```sh
cp deploy/.env.example deploy/.env   # set IMMICH_API_TOKEN
docker compose -f deploy/docker-compose.yml up -d
# Grafana on http://localhost:3000 → "Immich Library" dashboard
```

See [`deploy/`](deploy/) for Kubernetes (Deployment + Service + ServiceMonitor) and a Prometheus scrape example.

### Alerts

[`deploy/alerts.yml`](deploy/alerts.yml) holds alert rules: Immich or the exporter down, polls failing or stale, failing or stalled job queues, a filling or nearly full library volume, offline assets, integrity-check findings, a stale or shrunken database backup, users near their quota, and an available update. The compose stack loads them into Prometheus; for the Prometheus Operator, put the groups under the spec of a `PrometheusRule`; for VictoriaMetrics, pass the file to `vmalert -rule`.

### Immich's own metrics

Immich's built-in OpenTelemetry metrics complement these: enable them with `IMMICH_TELEMETRY_INCLUDE=all` and scrape **both** ports of the server container — `8081` for the API (request latency, database query timings) and `8082` for the microservices worker (job throughput and failures, `immich_jobs_*_total`). Scraping only `8081` misses every job metric.

## Configuration

Configuration is layered — each source overrides the one before it:

**built-in defaults → YAML file (`--config.file`) → environment variables → command-line flags**

Keep everything in one YAML file and still override a single value with an env var or flag at runtime. Run `immich-exporter --help` for the full list (each flag shows its `$ENV_VAR`).

### YAML config file

Point the exporter at a file with `--config.file=config.yml` (or `IMMICH_CONFIG_FILE`). Every key is optional; omitted keys keep their default, and unknown keys are rejected so typos fail loudly. Full template: [`deploy/config.example.yml`](deploy/config.example.yml).

```yaml
immich:
  base_url: http://immich-server:2283/api
web:
  listen_address: ":8000"
scrape: { interval: 2m, breakdown_interval: 15m, request_timeout: 20s }
collect: { camera: true, geo: true, ratings: true, people: false, heavy: true }
limits: { topn: 25, fanout_limit: 200, fanout_concurrency: 8, city_limit: 200 }
```

### Flags & environment variables

| Flag | Env var | Default | Description |
| --- | --- | --- | --- |
| `--immich.base-url` | `IMMICH_BASE_URL` | — | Full API base URL incl. `/api`; overrides host/port |
| `--immich.host` / `--immich.port` | `IMMICH_HOST` / `IMMICH_PORT` | `localhost` / `2283` | Immich location (API served under `/api`) |
| `--web.listen-address` | `EXPORTER_PORT` | `:8000` | Address/port to listen on |
| `--web.telemetry-path` | — | `/metrics` | Path to expose metrics under |
| `--immich.token-file` | `IMMICH_API_TOKEN_FILE` | — | File holding the API token, e.g. a mounted secret |
| `--scrape-interval` | `SCRAPE_INTERVAL` | `2m` | Cheap-metric poll interval (at least `10s`) |
| `--breakdown-interval` | `BREAKDOWN_INTERVAL` | `15m` | Refresh interval of the expensive collectors |
| `--collect.people` | `COLLECT_PEOPLE` | `false` | Per-person stats (one API call per person) |
| `--topn` / `--fanout.limit` | `TOPN` / `FANOUT_LIMIT` | `25` / `200` | Series cap / max distinct values per breakdown |
| `--geo.city-limit` | `GEO_CITY_LIMIT` | `200` | Cities kept in `immich_assets_by_city`; the rest sum into `other` (`0` keeps all) |
| `--log.level` | — | `info` | `debug`, `info`, `warn`, `error` |

| --- | --- | --- | --- |

### API token

The token is the one secret and is **never** a flag (it would show up in `ps`). Provide it, in order of precedence:

1. `IMMICH_API_TOKEN` environment variable (recommended)
2. A token file — `--immich.token-file`, `IMMICH_API_TOKEN_FILE`, or `immich.token_file` in YAML — for a mounted secret
3. `immich.token` in YAML — inline (discouraged; easy to commit by accident)

Use an **admin** key with the `all` permission for full coverage (`immich_key_is_admin` is `1`). A non-admin or scoped key degrades gracefully: whatever it may not read reports `immich_exporter_collector_success 0` under that collector's name, and the exporter logs it once.

## Metrics

Every series is prefixed `immich_` (plus standard `go_*` / `process_*`). Gauges unless noted; counters end in `_total`, byte values in `_bytes`. Roughly grouped:

| Group | Example series |
| --- | --- |
| Exporter health | `immich_exporter_up`, `immich_exporter_collector_success{collector}`, `immich_exporter_collector_duration_seconds`, `immich_key_is_admin` |
| Server | `immich_up`, `immich_server_info`, `immich_server_maintenance_mode`, `immich_server_update_available`, `immich_server_version_check_timestamp_seconds` |
| Integrity & backups | `immich_integrity_issues{type}`, `immich_database_backups`, `immich_database_backup_last_timestamp_seconds`, `immich_database_backup_last_size_bytes` |
| Assets | `immich_assets`, `immich_assets_by_year`, `immich_assets_by_rating`, `immich_assets_favorite`, `immich_assets_locked`, `immich_assets_by_file_size`¹ |
| Cameras & EXIF | `immich_assets_by_camera_make`, `_camera_model`, `_lens`, `immich_assets_with_camera`¹ |
| Geography | `immich_assets_by_country`, `immich_assets_by_city` (with `lat`/`lon`), `immich_assets_geotagged` |
| People & users | `immich_people`, `immich_person_assets`, `immich_assets_with_people`¹, `immich_user_usage_bytes`, `immich_user_storage_bytes{type}`, `immich_user_quota_bytes` |
| Albums & sharing | `immich_albums`, `immich_album_top_assets`, `immich_shared_links`, `immich_partners` |
| Content & jobs | `immich_tags`, `immich_memories`, `immich_duplicate_sets`, `immich_library_assets`, `immich_library_usage_bytes`, `immich_workflows`, `immich_job_queue` |

¹ Needs Immich 3.2+, whose search filters can express them. They count visible assets (timeline and archive), so they add up to the library size.

Instance-wide volumetrics, integrity checks, backups and job metrics require an **admin** key — `immich_key_is_admin` reports which mode you're in. Counts from Immich's search (states, ratings, years, cameras, places, file sizes) cover the key owner's library, and except for ¹ they include the hidden video half of each live photo, so they can exceed `immich_assets`. Scrape `/metrics` for the full set; liveness is at `/healthz`.

## Building

```sh
go build -o immich-exporter ./cmd/immich-exporter
go test -race ./...
golangci-lint run
```

See [CONTRIBUTING.md](CONTRIBUTING.md) for the dev workflow and [SECURITY.md](SECURITY.md) for the security policy — notably, don't expose `/metrics` publicly, as it carries library metadata (user/people/album names, geo centroids).
